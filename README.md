# Модель для классификации мин и камней при помощи ML модели
## Установка
1. Клонируйте репозиторий:
```bash
git clone  https://github.com/kmspokodu/big_data_lab2.git
```
2. Перейдите в директорию проекта:
```
cd big_data_lab2
``` 
3. Установите зависимости:
```
pip install -r requirements.txt
```
## Использование
1. Запустите скрипт для обучения модели:
```
python train.py
```
2. Для доступа к mongo используйте файл .env и подключитесь к базе данных с .env параметры подключения.   

3. Для классификации новых данных используйте API собрав контейнер с помощью Docker:
```
docker-compose up
```
4. Октрой в браузере http://localhost:55566 вы сможете протестировать API и классифицировать новые данные.

5. Чтобы порсмотреть записи в базе данных используйте следующую команду:

```
http://localhost:55566/api/v1/get-predictions/<id>
```

## Структура проекта
- `notebooks/` - директория для хранения Jupyter ноутбуков с экспериментами и анализом данных
- `src/` - директория для хранения исходного кода модели
- `data/` - директория для хранения данных
- `experiments/` - директория для хранения обученных моделей
- `train.py` - скрипт для обучения модели
- `predict.py` - скрипт для предсказания классов на новых данных
- `preprocess.py` - скрипт для предобработки данных
- `unit_tests/` - директория для хранения юнит-тестов
- `api.py` - скрипт для запуска API
- `static/` - директория для хранения статических файлов (например, HTML шаблонов для API)
- `requirements.txt` - файл для хранения зависимостей проекта
- `README.md` - файл с инструкциями по установке и использованию проекта
- `.env.example` - файл для хранения переменных окружения (например, параметры подключения к базе данных)
- `docker-compose.yml` - файл для настройки Docker контейнера для API
- `Dockerfile` - файл для настройки Docker образа для API
- `init-mongo.js` - скрипт для инициализации базы данных MongoDB с тестовыми данными
## CI/CD
Для автоматизации процесса разработки и развертывания модели используются Jenkins пайплайны для CI и CD. Пайплайн CI выполняет следующие шаги:
1. Клонирование репозитория
2. Установка зависимостей
3. Запуск юнит-тестов
4. Сборка Docker образа
Пайплайн CD выполняет следующие шаги:
1. Клонирование репозитория
2. Отправка Docker образа в Docker Hub
3. Развертывание Docker образа на сервере
4. Health check развернутого приложения
